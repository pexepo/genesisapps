# Forms → Discord Forum Bot (с review-флоу)

Бот принимает заявки на вступление и для каждой создаёт **новый пост в форум-канале**
с кнопками обработки. Заявки приходят **двумя способами**:

```
Сайт (папка web/) ───────────────────(HTTP POST /apply)──▶ bot.py ─▶ форум-канал
Google Forms ─(Apps Script onFormSubmit)─(HTTP POST /submit)─▶ bot.py ─▶ форум-канал
```

> 🌐 **Новое:** бот раздаёт собственный красивый сайт с формой (папка `web/`,
> тематика юнита **Genesis**, авто-язык RU/EN, анимации) — его можно использовать
> **вместо Google Forms**. См. раздел «[Сайт-заявка](#сайт-заявка-вместо-google-forms)».
>
> 💻 **Как запустить у себя на компьютере с нуля** — пошаговые гайды:
> **[README-macOS.md](README-macOS.md)** · **[README-Windows.md](README-Windows.md)**.
> Подключить свой домен: **[README-domain.md](README-domain.md)**.
> Полный production-деплой на Ubuntu с Cloudflare и исходящим прокси:
> **[README-Ubuntu-Cloudflare.md](README-Ubuntu-Cloudflare.md)**.

**Как выглядит обработка заявки:**

1. Приходит заявка → создаётся пост с embed и кнопками **Accept** / **Decline**;
   бот **пингует роль судей** `REVIEWER_ROLE_ID`. Кнопки работают только у участников
   с этой ролью.
2. **Decline** → ветке ставится тег **Declined**, если он настроен; имя ветки не
   меняется, кнопки гаснут.
3. **Accept** → ревьюеру приходит приватное (видно только ему) сообщение с
   4 кнопками ролей.
4. Ревьюер жмёт одну из 4 кнопок → бот **выдаёт эту роль заявителю** (по его
   подтвержденному Discord ID для сайта или юзернейму из Google Forms), вешает
   тег Accepted, если он настроен. Имя ветки при Accept и Decline не меняется.
   Публичное сообщение о решении не раскрывает, кто из ревьюеров нажал кнопку.
   Первые три кнопки дополнительно выдают `CORE_MEMBER_ROLE_ID`; четвёртая
   выдаёт только свою `ROLE_CHOICE_4_ID`.

## Шаг 1. Создать бота в Discord (подробно)

1. Зайди на **https://discord.com/developers/applications** под своим аккаунтом.
2. Жми **New Application** (правый верхний угол), задай имя → **Create**.
3. Слева открой вкладку **Bot**.
   - Нажми **Reset Token** → **Yes, do it!** → **Copy**. Это и есть `DISCORD_TOKEN`
     для `.env`. **Никому не показывай и не коммить его** — это пароль бота.
   - Прокрути до **Privileged Gateway Intents** и **включи**:
     - ✅ **SERVER MEMBERS INTENT** — обязателен, без него бот не сможет выдавать роли.
     - (MESSAGE CONTENT INTENT не нужен.)
   - Сохрани (**Save Changes**).
4. Слева **OAuth2 → URL Generator**:
   - В блоке **Scopes** отметь **`bot`**.
   - Появится блок **Bot Permissions** — отметь:
     - **View Channels**
     - **Send Messages**
     - **Create Public Threads**
     - **Send Messages in Threads**
     - **Manage Roles** (нужно для выдачи ролей)
     - **Manage Threads** (нужно, чтобы менять имя/теги ветки при смене статуса)
   - Внизу скопируй **сгенерированную ссылку**, открой её в браузере, выбери свой
     сервер → **Authorize**. Бот появится в списке участников (пока оффлайн).
5. **Иерархия ролей (важно!)** В Discord: **Настройки сервера → Роли**. Перетащи
   роль бота **ВЫШЕ** всех ролей, которые он будет выдавать (`ROLE_CHOICE_*`).
   Бот не может выдать роль, которая в списке выше его собственной.

### Как взять нужные ID

Включи **Режим разработчика**: Настройки Discord → **Расширенные** → *Режим разработчика*.
Дальше ПКМ по объекту → «Скопировать ID»:

| Что нужно             | Где взять                                   | Куда в `.env`        |
|-----------------------|---------------------------------------------|----------------------|
| ID форум-канала       | ПКМ по форум-каналу → Копировать ID канала  | `FORUM_CHANNEL_ID`   |
| ID роли-ревьюера      | Настройки сервера → Роли → ⋮ → Копировать ID | `REVIEWER_ROLE_ID`   |
| ID выдаваемых ролей   | там же                                       | `ROLE_CHOICE_1..4_ID`|

> Форум-канал создаётся так: ПКМ по категории → **Создать канал** → тип **Форум**.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

copy .env.example .env   # затем заполни значения в .env
python bot.py
```


теперь живёт на `http://localhost:8080/health` → `{"status": "ready", ...}`.

## Шаг 3. Сделать эндпоинт доступным из интернета

Apps Script работает на серверах Google, поэтому бот должен быть доступен извне:

- **VPS / хостинг с белым IP** — открой порт `PORT` в фаерволе.
- **Локально + туннель** (для теста):
  ```powershell
  ngrok http 8080
  # или
  cloudflared tunnel --url http://localhost:8080
  ```
  Туннель выдаст публичный `https://...`-адрес — подставь его в `apps_script.gs`
  как `BOT_URL` с путём `/submit` (напр. `https://abcd.ngrok-free.app/submit`).

> 🌐 По этому же адресу, но **без** `/submit` (напр. `https://abcd.ngrok-free.app/`),
> открывается встроенный **сайт-форма** — именно эту ссылку давай заявителям.
> Подробнее — в разделе «[Сайт-заявка](#сайт-заявка-вместо-google-forms)».

## Шаг 4. Подключить Google Forms (необязательно)

> Нужно **только** если хочешь принимать заявки через Google Forms. Если используешь
> встроенный сайт (раздел «[Сайт-заявка](#сайт-заявка-вместо-google-forms)» ниже) —
> этот шаг можно пропустить целиком.

1. Добавь в форму вопрос, куда заявитель впишет **свой Discord-юзернейм**
   (хэндл, напр. `ivan` — он уникальный). Числовой ID тоже подойдёт — бот понимает
   оба варианта. Без этого поля бот не сможет выдать роль.
   > Юзернейм (хэндл) виден в Настройках Discord → «Мой аккаунт». Это **не**
   > отображаемое имя/ник — по нику поиск ненадёжен (он не уникален).
2. Открой форму → меню «⋮» → **Script editor**.
3. Вставь содержимое `apps_script.gs`, заполни:
   - `BOT_URL` — публичный адрес эндпоинта (с `/submit`);
   - `SHARED_SECRET` — тот же, что в `.env`;
   - `APPLICANT_QUESTION` — часть названия твоего вопроса про Discord
     (напр. `"discord"`).
4. Слева **Triggers** (часики) → **Add Trigger**: функция `onFormSubmit`,
   источник *From form*, событие *On form submit*. Сохрани, выдай разрешения.

Отправь тестовый ответ — в форум-канале за пару секунд появится пост с кнопками.

### Как бот находит заявителя по юзернейму

При выборе роли бот резолвит строку из формы по порядку:
1. числовой ID или упоминание `<@id>` → напрямую;
2. **точный юзернейм-хэндл** (уникален) — основной надёжный путь;
3. global display name / ник на сервере (не уникальны — возможны промахи);
4. запрос к Discord API, если кэш участников неполный.

Если заявитель не найден (опечатка, ещё не вступил на сервер) — статус
**Accepted — <роль>** всё равно ставится, а в подсказке ревьюеру бот пишет,
что роль нужно выдать вручную. Для надёжного поиска по юзернеймам у бота должен
быть включён **Server Members Intent** (см. Шаг 1).

## Сайт-заявка (вместо Google Forms)

Бот раздаёт **собственный сайт** с формой вступления — тематический (юнит **Genesis**),
с авто-определением языка (**RU/EN** по локали и таймзоне браузера), пошаговым
мастером и анимациями. Открой публичный адрес бота из Шага 3 (или `http://localhost:8080/`
локально) — увидишь форму. Заявка уходит **напрямую боту** на `POST /apply`, и он сам
создаёт пост в форум-канале. Google Forms и Apps Script при этом **не нужны**.

### Discord login and daily application limit

The website can verify applicants through Discord OAuth2 instead of asking them
to type a username. In the Discord Developer Portal, open **OAuth2 → General**,
add the exact redirect URL (for example
`https://apply.example.com/auth/callback`), and configure:

```dotenv
DISCORD_CLIENT_ID=your-application-id
DISCORD_CLIENT_SECRET=your-oauth-client-secret
DISCORD_REDIRECT_URI=https://apply.example.com/auth/callback
SESSION_SECRET=a-separate-long-random-value
APPLICANT_ROLE_ID=optional-role-issued-on-submit
APPLICATION_COOLDOWN=86400
```

When all three `DISCORD_*` OAuth values are set, login is mandatory for website
applications. The server uses the verified Discord ID for role assignment and
allows one application per Discord account **and** source IP per 24 hours. The
limit is persisted in `STATE_FILE`, so restarting the bot does not reset it.
Only a keyed hash of the IP is stored. Set `TRUST_PROXY=1` only when a trusted
reverse proxy replaces `X-Forwarded-For`; otherwise clients could spoof their IP.

The bot needs **Manage Roles**, and its server role must be above
`APPLICANT_ROLE_ID` and every `ROLE_CHOICE_*` role.

**Маршруты HTTP-сервера:**

| Маршрут       | Метод | Назначение                                                 |
|---------------|-------|------------------------------------------------------------|
| `/`           | GET   | Сайт с формой (`web/index.html`)                           |
| `/assets/*`   | GET   | Стили, скрипт, логотип                                     |
| `/apply`      | POST  | Приём заявок с сайта (публичный, **без секрета**)          |
| `/submit`     | POST  | Приём из Google Forms (с `X-Auth-Token`) — как и раньше    |
| `/health`     | GET   | Проверка состояния: `{"status":"ready", ...}`              |

**Почему `/apply` без секрета — и не опасно ли это.** Форма открыта всем желающим,
поэтому общий секрет в браузер не кладём (его было бы видно в коде страницы). Вместо
этого эндпоинт защищён:

- **honeypot** — скрытое поле-ловушка: если оно заполнено (признак бота), заявка
  молча отбрасывается;
- **рейт-лимит по IP** — не больше `APPLY_RATE_MAX` заявок за `APPLY_RATE_WINDOW` секунд
  (реальный IP берётся из `X-Forwarded-For` за туннелем);
- **валидация** — обязательные поля, лимиты длины ответов, ограничение размера запроса.

**Поля формы:** Discord-юзернейм (по нему выдаётся роль — как и в Google Forms),
программа для эдитинга, любимый стиль эдитинга, цель вступления, ссылка на лучшую
работу, ссылка на соцсеть с работами. Тексты, языки и набор полей правятся в
`web/assets/app.js` (объект `I18N` и массив `FIELDS`) и `web/index.html`.

**Логотип** берётся из `web/assets/genesis-logo.png` (сконвертирован из `gsslogo.ai`)
и перекрашивается в фирменный градиент прямо в CSS — отдельная картинка-белый-вариант
не нужна. Иконка вкладки — `web/assets/favicon.svg`.

**Дополнительные переменные `.env`** (все необязательные, есть значения по умолчанию):

| Переменная          | По умолчанию       | Назначение                                 |
|---------------------|--------------------|--------------------------------------------|
| `APPLY_RATE_MAX`    | `5`                | Сколько заявок с одного IP разрешено        |
| `APPLY_RATE_WINDOW` | `600`              | За сколько секунд считается этот лимит       |
| `APPLY_FORM_TITLE`  | `Заявка в Genesis` | Заголовок поста-заявки, пришедшей с сайта    |

> Можно держать **оба** канала приёма одновременно: сайт (`/apply`) и Google Forms
> (`/submit`) работают параллельно и не мешают друг другу. Внешний вид поста-заявки
> настраивается теми же `EMBED_*` (см. «Кастом embed»).

## Теги статуса (необязательно)

Чтобы статус был ещё и форум-тегом (а не только в имени ветки):

1. Настройки форум-канала → раздел **Теги** → создай теги, напр. `Accepted` и `Declined`.
2. Узнай ID тега: ПКМ по любому посту → реакции тут не помогут, поэтому проще —
   создай пост, повесь тег, и в логах бота при смене статуса ID видно; либо
   используй Discord API. Самый простой путь: оставь `ACCEPTED_TAG_ID` /
   `DECLINED_TAG_ID` пустыми — тогда статус будет только в **имени ветки**
   (`✅ Accepted — Роль` / `⛔ Declined`), и настройка тегов не нужна.

> Если теги не заданы, всё работает — статус просто отражается в названии ветки.

## Кастом embed (полностью через `.env`)

Внешний вид поста-заявки настраивается переменными окружения — **код менять не
нужно**. Все поля необязательны: оставь пустым → берётся значение по умолчанию.

| Переменная             | Что делает                                                            | Пример                          |
|------------------------|----------------------------------------------------------------------|---------------------------------|
| `EMBED_COLOR`          | Цвет полоски слева. HEX: `#5865F2`, `5865F2` или `0x5865F2`. Пусто = blurple. | `#FF0066`                |
| `EMBED_TITLE`          | Заголовок эмбеда. Пусто = название формы. Поддерживает плейсхолдеры.  | `Новая заявка: {form_title}`    |
| `EMBED_FOOTER`         | Текст футера. Пусто = футер скрыт. Поддерживает плейсхолдеры.         | `Подал: {responder}`            |
| `EMBED_FOOTER_ICON`    | URL иконки рядом с футером (`https://...`).                           | `https://site/ico.png`          |
| `EMBED_THUMBNAIL`      | URL маленькой картинки справа-вверху.                                 | `https://site/logo.png`         |
| `EMBED_IMAGE`          | URL большой картинки внизу эмбеда.                                    | `https://site/banner.png`       |
| `EMBED_AUTHOR_ICON`    | URL иконки рядом с автором (отправителем).                            | `https://site/ava.png`          |
| `EMBED_SHOW_AUTHOR`    | Показывать отправителя (email/имя) как автора: `1` / `0`.             | `1`                             |
| `EMBED_SHOW_TIMESTAMP` | Показывать время заявки в футере: `1` / `0`.                          | `1`                             |

**Плейсхолдеры** (работают в `EMBED_TITLE` и `EMBED_FOOTER`):
- `{form_title}` — название Google-формы;
- `{responder}` — email/имя отправителя (или «Аноним»).

**Важно про картинки:** Discord принимает только прямые HTTPS-ссылки на
изображение (URL должен заканчиваться на `.png`/`.jpg`/`.gif` и открываться в
браузере как картинка). Ссылка на страницу-галерею или Google Drive «share»-линк
работать не будет — нужен прямой линк на файл.

Пример «брендированного» поста в `.env`:
```dotenv
EMBED_COLOR=#FF0066
EMBED_TITLE=📨 Новая заявка
EMBED_FOOTER=Гильдия «Пример» • {responder}
EMBED_THUMBNAIL=https://i.imgur.com/your_logo.png
EMBED_SHOW_AUTHOR=1
EMBED_SHOW_TIMESTAMP=1
```

Каждое поле «вопрос → ответ» из формы добавляется автоматически (до 25 полей —
лимит Discord). Длинные значения подрезаются под лимиты Discord
(заголовок 256, значение поля 1024 символа).

После изменения `.env` **перезапусти бота**, чтобы настройки применились.

## Шаг 5. Деплой на VPS — подробно для новичка

Локально бот работает, только пока у тебя открыт терминал. Чтобы он работал
**24/7** (сам запускался при включении сервера и перезапускался, если упал),
его ставят на **VPS** — это арендованный компьютер в дата-центре, который не
выключается. Ниже — пошагово, с нуля, для Ubuntu (22.04/24.04).

> **Что мы в итоге сделаем:** арендуем VPS → подключимся к нему → зальём код →
> настроим автозапуск через systemd → откроем доступ для Google-формы.
>
> **Соглашение:** строки, начинающиеся с `$`, — это команды, которые ты вводишь
> в терминале сервера (сам символ `$` набирать не нужно). `sudo` означает
> «выполнить от имени администратора».

### 5.0. Арендовать VPS

1. Зарегистрируйся у любого хостера VPS (например Timeweb, Aeza, Hetzner,
   DigitalOcean — любой). Возьми самый дешёвый тариф, этого хватит.
2. При создании сервера выбери **операционную систему Ubuntu 22.04** (или 24.04).
3. После создания хостер пришлёт три вещи: **IP-адрес** сервера (вида
   `123.45.67.89`), **логин** (обычно `root`) и **пароль**. Они нужны для входа.

### 5.1. Подключиться к серверу (SSH)

«Зайти на сервер» = подключиться по SSH из терминала твоего компьютера.

**На Windows** открой **PowerShell** (он уже установлен) и введи, подставив свой IP:

```powershell
ssh root@123.45.67.89
```

Первый раз спросит `Are you sure you want to continue connecting?` — напиши `yes`
и Enter. Потом попросит пароль — вставь его (при вводе пароль **не отображается**,
это нормально) и нажми Enter. Если увидел приглашение вида `root@server:~#` —
ты внутри сервера. Все следующие команды вводишь **здесь**, а не у себя.

> Чтобы выйти с сервера обратно к себе — команда `exit`.

### 5.2. Установить нужные программы

Скопируй и вставь целиком (в PowerShell/SSH вставка — правый клик мыши):

```bash
sudo apt update && sudo apt install -y python3 python3-venv git
```

Это обновляет список пакетов и ставит Python, модуль виртуальных окружений и git.
Дождись, пока команда закончится и снова появится приглашение.

### 5.3. Создать отдельного пользователя для бота

Запускать бота под `root` небезопасно. Заведём служебного пользователя `botuser`,
от имени которого бот будет жить в папке `/opt/formsbot`:

```bash
sudo adduser --system --group --home /opt/formsbot botuser
```

### 5.4. Залить код бота на сервер

Есть два пути — выбери один.

**Вариант А — через git** (если код лежит в GitHub/GitLab). Замени ссылку на свою:

```bash
sudo -u botuser git clone https://github.com/твой-логин/твой-репозиторий.git /opt/formsbot/app
```

**Вариант Б — скопировать с своего компьютера** (если репозитория нет).
Выполни эту команду **в новом окне PowerShell у себя** (не на сервере), указав
путь к папке проекта и IP сервера:

```powershell
scp -r "C:\Users\pexep\Downloads\ezezez\*" root@123.45.67.89:/opt/formsbot/app/
```

Если папки `/opt/formsbot/app` ещё нет, сначала создай её на сервере:
`sudo mkdir -p /opt/formsbot/app`, и после копирования передай её боту:
`sudo chown -R botuser:botuser /opt/formsbot/app`.

Дальше зайди в папку проекта (на сервере):

```bash
cd /opt/formsbot/app
```

### 5.5. Установить зависимости бота

Создаём «виртуальное окружение» (изолированный Python только для этого бота) и
ставим в него библиотеки из `requirements.txt`:

```bash
sudo -u botuser python3 -m venv /opt/formsbot/venv
sudo -u botuser /opt/formsbot/venv/bin/pip install -r requirements.txt
```

### 5.6. Заполнить `.env` боевыми значениями

```bash
sudo -u botuser cp .env.example .env
sudo -u botuser nano .env
```

Откроется текстовый редактор **nano** прямо в терминале. Впиши свои значения
(токен, ID канала и ролей, `SHARED_SECRET`, настройки embed — всё как в Шагах 1–4).
Перемещение — стрелками. Когда закончил:

- **Ctrl + O**, затем **Enter** — сохранить;
- **Ctrl + X** — выйти из nano.

Закроем файл от чужих глаз (секреты сможет читать только владелец):

```bash
sudo chmod 600 /opt/formsbot/app/.env
sudo chown botuser:botuser /opt/formsbot/app/.env
```

### 5.7. Настроить автозапуск (systemd)

**systemd** — встроенный в Linux «менеджер служб». Мы опишем бота как службу, и
система сама будет его запускать при загрузке и поднимать после падения.

Создай файл службы командой (она откроет пустой файл в nano):

```bash
sudo nano /etc/systemd/system/formsbot.service
```

Вставь в него этот текст **без изменений** (если все пути выше совпадают):

```ini
[Unit]
Description=Forms -> Discord Forum Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=botuser
Group=botuser
WorkingDirectory=/opt/formsbot/app
EnvironmentFile=/opt/formsbot/app/.env
ExecStart=/opt/formsbot/venv/bin/python /opt/formsbot/app/bot.py
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
```

Сохрани и выйди (**Ctrl+O**, Enter, **Ctrl+X**).

> Что значат строки: `User` — под кем запускать; `WorkingDirectory` — рабочая
> папка (чтобы `submissions.json` лёг рядом с ботом); `EnvironmentFile` —
> подгрузить переменные из `.env`; `ExecStart` — какую команду выполнить;
> `Restart=on-failure` — перезапускать при сбое. Менять ничего не нужно, если ты
> использовал пути из этого гайда.

### 5.8. Запустить бота

```bash
sudo systemctl daemon-reload            # перечитать файлы служб
sudo systemctl enable --now formsbot    # включить автозапуск И запустить сейчас
sudo systemctl status formsbot          # посмотреть состояние
```

Если в `status` видишь зелёное **active (running)** — бот работает. Выйти из
просмотра статуса — клавиша **q**.

### 5.9. Проверить логи и управлять ботом

```bash
journalctl -u formsbot -f          # живые логи (выйти — Ctrl+C)
journalctl -u formsbot -n 100      # последние 100 строк логов
sudo systemctl restart formsbot    # перезапустить (обязательно после правок .env!)
sudo systemctl stop formsbot       # остановить
sudo systemctl start formsbot      # запустить снова
```

При удачном старте в логах будет:
```
HTTP-сервер слушает http://0.0.0.0:8080  (сайт: есть, POST /apply, POST /submit)
Бот вошёл как ИмяБота#1234
Форум-канал найден: #заявки
```

> **Важно:** после любого изменения `.env` бот надо перезапустить
> (`sudo systemctl restart formsbot`) — иначе он работает со старыми значениями.

### 5.10. Открыть доступ для Google-формы

Google Apps Script стучится к боту **снаружи**, по адресу `BOT_URL`. Значит,
эндпоинт `/submit` должен быть доступен из интернета. Самый простой рабочий
вариант для новичка:

1. Открой порт в фаерволе сервера:
   ```bash
   sudo ufw allow 8080/tcp
   sudo ufw allow OpenSSH       # чтобы не потерять доступ по SSH
   sudo ufw enable              # включить фаервол (напишет y/n — ответь y)
   ```
2. В `apps_script.gs` (см. Шаг 4) пропиши адрес с IP сервера:
   ```
   var BOT_URL = "http://123.45.67.89:8080/submit";
   ```
3. Проверь из браузера: открой `http://123.45.67.89:8080/` — должно показать
   `{"status": "ready", ...}`.
4. Отправь тестовый ответ формы — в форум-канале появится пост.

> ⚠️ Это обычный **HTTP без шифрования**. Эндпоинт защищён секретом
> `SHARED_SECRET`, так что чужой пост создать не сможет, но трафик не зашифрован.
> Для «по-взрослому» позже можно прикрутить домен и HTTPS — см. ниже.

#### (Необязательно) Домен + HTTPS

Когда освоишься, можно сделать красивый адрес `https://bot.твойдомен/submit`:
поставить перед ботом **reverse-proxy** (nginx или Caddy), выпустить бесплатный
сертификат Let's Encrypt и проксировать запросы на `127.0.0.1:8080`. Тогда в
`.env` ставят `HOST=127.0.0.1` (бот слушает только локально), а наружу открыт
только порт 443. Caddy делает HTTPS почти автоматически — это самый лёгкий путь.
Если своего домена/белого IP нет — выручит **Cloudflare Tunnel** (`cloudflared`):
он даёт постоянный HTTPS-адрес без проброса портов.

## Опции `.env` (кратко)

| Переменная           | Назначение                                                        |
|----------------------|-------------------------------------------------------------------|
| `DISCORD_TOKEN`      | Токен бота                                                         |
| `FORUM_CHANNEL_ID`   | Куда создавать посты (форум-канал)                                 |
| `REVIEWER_ROLE_ID`   | Роль, которой разрешены кнопки Accept/Decline и выбор роли         |
| `PING_REVIEWER`      | Пинговать роль судей в новом посте-заявке (1/0, по умолчанию 1)    |
| `ROLE_CHOICE_1..4_*` | 4 кнопки выбора роли: `_ID` — выдаваемая роль, `_NAME` — подпись   |
| `CORE_MEMBER_ROLE_ID` | Дополнительная роль для вариантов 1-3; вариант 4 её не получает   |
| `APPLICANT_ROLE_ID` | Роль, выдаваемая сразу после подтвержденной заявки с сайта          |
| `ACCEPTED_TAG_ID` / `DECLINED_TAG_ID` | Форум-теги статуса (необязательно)                |
| `DEFAULT_TAG_IDS`    | Теги, вешаемые на каждый новый пост (через запятую)               |
| `EMBED_*`            | Внешний вид поста-заявки (см. раздел «Кастом embed»)              |
| `SHARED_SECRET`      | Секрет для защиты `/submit` (совпадает с Apps Script)            |
| `HOST` / `PORT`      | Где слушать входящие запросы (сайт + POST)                         |
| `STATE_FILE`         | Файл состояния (дедуп + работа кнопок после рестарта)             |
| `APPLY_RATE_MAX` / `APPLY_RATE_WINDOW` | Антиспам сайта: лимит заявок с одного IP и окно (сек) |
| `APPLY_FORM_TITLE`   | Заголовок поста для заявок с сайта (`/apply`)                     |
| `OUTBOUND_PROXY` / `PROXY_*` | Необязательный HTTP(S)-прокси для Discord API/Gateway/OAuth |

## Дедупликация и устойчивость

- Каждый ответ формы имеет уникальный `response_id` — повторные/ретрай-отправки
  игнорируются, дубль-пост не создаётся.
- Состояние заявок хранится в `STATE_FILE` (`submissions.json`, атомарная запись).
  Благодаря этому кнопки **работают и после перезапуска бота** (persistent views).

## Безопасность

Эндпоинт `/submit` защищён заголовком `X-Auth-Token` (constant-time сравнение с
`SHARED_SECRET`). Запросы без верного секрета отклоняются (401). Используй длинный
случайный секрет и HTTPS-туннель/реверс-прокси.

Эндпоинт сайта `/apply` **публичный** (форма открыта всем), поэтому защищён иначе:
honeypot-полем, рейт-лимитом по IP (`APPLY_RATE_MAX` / `APPLY_RATE_WINDOW`) и
валидацией размеров. Если форма должна быть доступна только «своим» — закрой адрес
на уровне реверс-прокси (Basic-auth, allowlist по IP, Cloudflare Access и т.п.).
